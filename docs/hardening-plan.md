# Hardened fork implementation

Status: implementation in progress. This is not a production certification.

## Scope and binding decisions

Repair the audited addon at 3b856fa68892f3a8e1c4548cdc46b649b87de0e2. Keep official Obsidian Sync and optional Git/reMarkable ingestion. Provide an intentionally read-only MCP interface using the official Python MCP SDK. Administration uses Home Assistant's managed addon options, replacing the two unprotected credential web servers. OAuth and MCP mutations are not supported in this initial hardened profile; reject obsolete options rather than pretending they work. Tunnels belong to separate infrastructure.

No deployment to a real HA instance, real accounts, personal vaults or upstream repository. The requested fork and its development branch are authorized. Never include personal project material or credentials in public source code.

## Data contract

Each source owns a distinct workspace: `/data/obsidian`, `/data/git`, `/data/remarkable`. The live Obsidian vault is `/data/obsidian/vault`; no share mount. reMarkable generated output is `/data/remarkable/generated`; original downloads and conversion state stay private to that service. Git never adopts a pre-existing user directory.

Publisher API: `hardened.snapshots.publish(source_root: Path, publication_root: Path, *, source: dict) -> dict`. Publication roots are `/data/published/obsidian`, `/data/published/git`, `/data/published/remarkable`. Each has immutable `generations/<generation>/files/...` and `generations/<generation>/manifest.json`. `current.json` contains `{schema_version: 1, generation: <safe id>}`. Manifest contains `{schema_version: 1, generation: <id>, created_at: <UTC ISO>, source: <dict>, files: {relative_path: {sha256: <hex>, size: <int>}}}`. Publish current only after durable complete generation. Retain three recent generations plus actively leased older ones. Each complete generation has a regular single-link .lease (0640); readers hold a shared flock for the whole operation, retirement needs a nonblocking exclusive flock. At most eight retained generations and 2 GiB logical publication bytes per source; preserve 256 MiB filesystem free-space reserve. Reuse unchanged validated content/revision; clean only owned staging/retired generations. Original sources are outside this derived-data cleanup. Source names and paths are validated; symlinks, hardlinked source files, special files, hidden paths and oversized inputs are rejected/skipped with explicit policy. Reader pins a validated generation per request and opens contained regular files without following symlinks. Publication records source revision and last successful acquisition. Obsidian acquisition is one-shot pull-only sync followed by publication; no concurrent sync writer during publication. reMarkable acquisition is one-shot conversion followed by publication only on success. Git uses immutable commit trees.

UIDs: obsidian 10001, git 10002, remarkable 10003, mcp 10004. Private service directories 0700 owner service. `/data/published` root-owned 0755. Source publication root owned source UID, group 10004, mode 02750; descendants files 0640/directories 0750 with reader group. MCP only reads publications and owns separate writable state in `/data/mcp`. Source processes can be supplementary members of group 10004; none can write peers' publications or access their private credentials. Root bootstrap reads options and drops privileges before starting a service. Child environments are constructed per service; no shared secret export.

## Task 1 — Runtime and configuration

Owner runtime implementer. Files: `config.yaml`, `translations/en.yaml`, all `rootfs/**`, new `hardened/runtime.py`, `hardened/config.py`, `tests/test_runtime.py`. Do not modify Dockerfile, Go code, reader.py, snapshots.py or git_sync.py.

Provide fail-closed validated options; no published credential ports or share/ssl mounts; MCP port 8420 default unbound, authenticated TLS with operator-supplied certificate/key when exposed. New slug `obsidian_headless_hardened`, version `0.1.0-dev`, repository URL points to intended fork `kamikazaaa/hassio-obsidian-headless`; remove `image` until a verified release exists (local builds). Docker final base is the official pinned Home Assistant Debian image with its s6 runtime and pinned Python 3.12/Node runtimes.

Service launch contract `python3 -m hardened.runtime <obsidian|git|remarkable|mcp>`. Runtime owns directory bootstrap/privilege separation and loops/status per service. Obsidian executes official `ob sync-setup` with argument list, verifies actual configured vault identity, uses `ob sync-config --mode pull-only` and one-shot `ob sync`, then publishes. Changes of configured source identity must fail visibly with safe fresh-instance guidance, never automatically relink an existing workbench. Failed setup cannot create a success marker. Git calls `hardened.git_sync.sync_once(config, state_root, publication_root)`; define config mapping with `git_repos` string + `git_auth_token` optional, no arbitrary path inputs. Remarkable executes Go binary once with `SYNC_ONCE=true` and isolated `VAULT_PATH=/data/remarkable/generated`, fixed output subfolder `documents` (or coordinate with importer). Optional pairing code passed via stdin to rmapi, never command-line, and never re-paired automatically after successful credentials exist. MCP calls `hardened.reader.run(...)` or module configured by private per-service env. Coordinate exact interface with reader owner.

Keep service status outside publications, provide status command usable for healthcheck (exit nonzero on configured service failure/staleness; distinguish disabled from broken). No `sleep inf` on fatal misconfiguration. Rate-limit retry loops. Use real behavior tests for special-character argument handling, denied path/symlink/config changes, per-service secrets, and actual privilege separation where supported. Record red and green evidence.

## Task 2 — reMarkable integrity

Owner imports implementer. Files: `remarkable-sync/**` only. Remove both custom auth/register web servers from the runnable daemon and remove their now unused packages. Pairing is handled through runtime managed options. Preserve conversion features; native pen-stroke OCR is explicitly unsupported unless actually implemented/tested.

Support `SYNC_ONCE=true`: one acquisition/conversion run, successful exit only when required outputs and index succeed. Work only in own generated tree (default VAULT_PATH changed safely). Cache keyed by source content hash, conversion version and effective config, validates output hashes/existence, regenerates missing output, detects manual output modifications rather than overwrites, retries partial failures. Keep original bundles; bounded archive expansion/file count/metadata/image/PDF sizes; reject escaping paths and symlinks; validate output directory. Reserved collection index separate from document names. Treat partial OCR/PDF failures correctly; optional OCR policy explicit, no completed stamp on required failure. Atomic durable file writes/state; propagate all errors; preserve last good outputs on error. Write behavioral tests for audit regressions, disk/write faults, annotations/manual modifications, traversal, same-mtime changed bytes, config changes and index-name collisions. Existing full Go suite must pass; update expectations only for deliberate documented product changes.

## Task 3 — Read-only MCP

Owner reader implementer. Files: `hardened/reader.py`, `tests/test_reader.py`, `requirements.in`, `requirements.lock`, `pyproject.toml` if needed. Do not modify runtime/config, Go, snapshots or build files. Use official pinned MCP Python SDK (v1 compatible FastMCP) rather than an ad-hoc JSON-RPC implementation. Implement list, read, bounded search with explicit source namespace and provenance against manifest format above. No mutation, uploads, arbitrary command tools or unbounded indexes. Always require strong bearer token, correct missing/invalid auth responses; trusted host/origin policy; TLS required for remote listen. No OAuth claims/half configured flow. Coordinate startup environment/signature with runtime owner. Ensure ASGI authentication protects all document routes; authenticated MCP list/call integration test through official SDK transport if possible. Real OS-level reader permissions tested by runtime owner, reader tests enforce safe filesystem opens and generation pinning. Enforce size/count/query/result limits, UTF-8 errors and corruption handling; no automatic execution of document content. No symlink/hardlink/path escapes, including malformed current/manifest paths.

## Task 4 — Publication, Git, build and docs

Root integration. Files: `hardened/snapshots.py`, `hardened/git_sync.py`, package init, publisher/git tests, Dockerfile, workflows, README/DOCS/SECURITY/validation docs. Git source identities are hash-based and include normalized remote+branch; no destructive adoption, no hooks/submodules/LFS execution, tokens scoped to configured HTTPS host, no credentials in logs or URLs, bounded commands and safe archive extraction. Publication is durable, immutable and verified; snapshots exclude secret/config/control paths, have resource limits, retain old good generation on failure.

Build minimal image with known pinned base/toolchain/SDK/package versions and lock integrity; no runtime package installs or remote shell scripts. Do not automatically publish images or write upstream addon distribution. Run tests, actual builds when toolchain permits, independent cross-component review and fix findings before committing the final development deliverable. CI builds supported amd64/arm64 but never report it passed without execution. Document manual actual-HA/cloud account/restore acceptance gates honestly.
